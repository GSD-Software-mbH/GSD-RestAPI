# Migration von 0.2 auf 0.3

0.3 ist ein reines Dart-Paket mit einem Einstieg, `GsdApiClient`. Die Gruppen `v1`, `v3` und
`raw` bleiben, ebenso Session-Erneuerung, 2FA, Batching und Uploads. Anders sind die Namen,
die Rückgabewerte und die Fehlerbehandlung:

- Ein Endpunkt liefert ein Modell oder das dekodierte `data`, keine `RestApiResponse`.
- Ein Fehlerstatus wirft eine `GsdApiException`, statt `isOk` zu setzen.
- V3-Methoden nehmen Request-Modelle statt JSON-Strings.
- Ereignisse kommen als Streams, nicht als Callbacks.

Die Legacy-Fassade `RestApiDOCUframeManager` ist schon in 0.3 entfernt. Wer noch auf ihr
steht, stellt zuerst auf `DOCUframeApi` aus 0.2 um und folgt dann diesem Leitfaden.

## Import

```dart
// vorher
import 'package:gsd_restapi/docuframe_api.dart';
import 'package:gsd_restapi/src/runtime/api_runtime.dart';

// nachher: das einzige Barrel
import 'package:gsd_restapi/gsd_restapi.dart';
```

`package:gsd_restapi/src/…` ist intern. Die Extensions auf `String`, `DateTime` und
`ISODuration` gehören nicht mehr zur API (`toMd5Hash` entfällt ganz); den MD5-Hash des
Passworts bildet die Anwendung selbst, etwa mit `package:crypto`:

```dart
// vorher
final md5Password = password.toMd5Hash();

// nachher
final md5Password = md5.convert(utf8.encode(password)).toString();
```

## Konstruktor

```dart
// vorher
final api = DOCUframeApi(
  configuration: RestApiDOCUframeConfig(
    appKey: appKey,
    userName: userName,
    appNames: ['GSD-DFApp'],
    serverUrl: serverUrl,
    alias: alias,
    sessionId: storedSessionId,
  ),
  callbacks: callbacks,
);

// nachher
final api = GsdApiClient(
  configuration: GsdApiConfig(
    appKey: appKey,
    userName: userName,
    appNames: const ['GSD-DFApp'],
    serverUrl: serverUrl,
    alias: alias,
  ),
  sessionId: storedSessionId,
  twoFactorTokenProvider: askForTwoFactorToken,
);
```

`GsdApiConfig` ist unveränderlich: Die Setter `setMaxBufferSize`, `setBufferFlushDelayMs`,
`setPerPageCount` und `setAllowSslError` entfallen, `additionalAppNames` ist ein
Konstruktorparameter. `getUri`, `getHeaders`, `getAllAppNames` und `debugLogs` entfallen ohne
Ersatz; Adresse und Header baut der Client selbst. Eine gespeicherte Session geht an
`GsdApiClient(sessionId:)` und löst kein Ereignis aus; erneuern lässt sie sich erst nach
`v1.authentication.setPassword`.

`v1`, `v3` und `raw` am Client und die Gruppen darunter sind `final`.

## Callbacks → Streams

```dart
// vorher
callbacks: RestApiDOCUframeCallbacks(
  onSessionIdChanged: (sessionId) async => store(sessionId),
  onLicenseWrong: (e) async => showLicenseError(e),
  onUserAndPassWrong: (e) async => showLogin(),
  onMissing2FAToken: () async => askForTwoFactorToken(),
  onLogMessage: (message) => log(message),
  onHttpMetricRecorded: (metric) => record(metric),
),

// nachher
final subscriptions = [
  api.sessionIdChanges.listen(store),
  api.licenseErrors.listen(showLicenseError),
  api.invalidCredentials.listen((_) => showLogin()),
  api.logs.listen(log),
  api.httpMetrics.listen(record),
];
// den 2FA-Token liefert GsdApiClient(twoFactorTokenProvider: askForTwoFactorToken)

await api.dispose();
for (final subscription in subscriptions) {
  await subscription.cancel();
}
```

- Die Streams sind synchrone Broadcast-Streams. Ein Ereignis kommt an, während der Client es
  meldet, also vor der Exception beim Aufrufer.
- Ohne Listener geht ein Ereignis verloren. Deshalb direkt nach dem Konstruktor zuhören und das
  Abo erst nach `await dispose()` kündigen.
- Der `twoFactorTokenProvider` wird nur bei einem 341 **innerhalb** einer Sitzung gefragt
  (Refresh), nie beim expliziten `login()`. Dort wirft `GsdTwoFactorTokenMissingException` an
  den Aufrufer. Wirft der Provider, gilt das wie `''` und erscheint in `logs`.
- `v1.authentication.login` hat keinen Parameter `refreshSession` mehr.

## V3-Body → Modell

```dart
// vorher
final response = await api.v3.objectData.getById(
  body: jsonEncode([
    {'classId': 100, 'type': '', 'context': 'edit', 'ids': [200, 201]},
  ]),
);

// nachher
final objects = await api.v3.objectData.getById([
  const GsdObjectsByIdRequest(classId: 100, context: 'edit', ids: [200, 201]),
]);
```

| Methode | Request | Rückgabe |
|---|---|---|
| `v3.model.structure` | `List<GsdStructureRequest>` | `List<Object?>` (`data`) |
| `v3.objectData.getById` | `List<GsdObjectsByIdRequest>` | `List<Object?>` (`data`) |
| `v3.objectData.getByQuery` | `List<GsdObjectsByQueryRequest>` | `List<Object?>` (`data`) |
| `v3.objectData.getByParentObject` | `List<GsdObjectsByParentRequest>` | `List<Object?>` (`data`) |
| `v3.view.load` | `List<GsdViewLoadRequest>` | `List<Object?>` (`data`) |
| `v3.view.action` | `GsdViewActionRequest(actionOid:, tryCount:, payload:)` | `Map<String, Object?>` (ganzer Body) |
| `v3.system.versionInfo` | – | `Map<String, Object?>` (`data`) |
| `v3.system.appConfig`, `v3.system.appTheme` | – | `List<Object?>` (`data`) |
| `v3.file.get` | – | `GsdFileDownload` |

`jsonEncode(request.toJson())` ist byte-gleich zu dem, was die App bisher gesendet hat. Fehlt in
der Antwort das `data`-Array, wirft die Methode `GsdParseException`, statt eine leere Liste zu
liefern.

## `httpResponse.body` → Rückgabe

```dart
// vorher
final response = await api.v1.objects.getObject(oid);
if (response.isOk) {
  final data = jsonDecode(response.httpResponse.body)['data'];
}

final file = await api.v1.documents.getFile(oid);
final bytes = file.httpResponse.bodyBytes;

// nachher
final data = await api.v1.objects.getObject(oid); // Object?: das dekodierte data

final file = await api.v1.documents.getFile(oid); // GsdFileDownload
final bytes = file.bytes;
final contentType = file.headers['content-type'];
```

- Endpunkte mit bekannter Antwortform liefern ein Modell (Tabelle [Namen](#namen)), alle übrigen
  V1-Endpunkte das dekodierte `data` als `Object?`.
- `v1.documents.getPreview` liefert die Bytes oder `null`.
- `GsdFileUploadController.result` liefert `data` als `Object?`.
- Nur `raw.request` gibt noch eine rohe Antwort zurück (`GsdRawApiResponse` mit `statusCode`,
  `headers`, `body`, `bodyBytes`).

## Exceptions

Alle Exceptions erben von der `sealed`-Basis `GsdApiException` (`message`); ein `switch`
darüber ist erschöpfend.

| 0.2 | 0.3 |
|---|---|
| `WebServiceException` (`statusCode`) | `GsdServerException` (`internalStatus`, `statusMessage`) |
| `SessionInvalidException` | `GsdSessionInvalidException` (201) |
| `TokenOrSessionIsMissingException` | `GsdSessionMissingException` (204) |
| `UserAndPassWrongException` | `GsdInvalidCredentialsException` (302) |
| `LicenseException` | `GsdLicenseException` (306, 101) |
| `Require2FALoginException` | `GsdTwoFactorRequiredException` (340) |
| `Missing2FATokenException` | `GsdTwoFactorTokenMissingException` (341) |
| `Invalid2FATokenException` | `GsdTwoFactorTokenInvalidException` (342) |
| `HttpRequestException` | `GsdHttpException` (`statusCode` als `int`, `reasonPhrase`) |
| `SecurityException` | `GsdSecurityException` |
| `FormatException`, `TypeError` beim Lesen der Antwort | `GsdParseException` (`operationId`, `path`) |
| String `'Upload cancelled'` | `GsdUploadCancelledException` |

```dart
// vorher
final response = await api.v1.objects.getObjects('Dokument');
if (!response.isOk) {
  showError(response.statusMessage);
}

// nachher
try {
  final objects = await api.v1.objects.getObjects('Dokument');
} on GsdApiException catch (error) {
  switch (error) {
    case GsdServerException(:final statusMessage):
      showError(statusMessage);
    case GsdHttpException() || GsdParseException():
      showTechnicalError(error);
    case GsdSecurityException() || GsdUploadCancelledException():
      rethrow;
  }
}
```

- Wer eine `GsdServerException` selbst erzeugt (etwa in Tests), übergibt die Felder benannt:
  `GsdLicenseException(internalStatus: '306', statusMessage: 'abgelaufen')`, `message:` ist
  optional. In 0.2 waren es drei positionale Strings.
- Transportfehler (`SocketException`, `ClientException`, `TimeoutException`) gehen unverändert
  durch.
- `v1.integrations.postExecuteInterfaceMacro` wertet jetzt den Status aus wie jeder andere
  Endpunkt: Session-Refresh, Retry und 2FA-Abfrage gelten auch dort, und ein Fehlerstatus wirft.
- Ein abgebrochener Upload endet mit `GsdUploadCancelledException`. Ein `cancel()` nach dem
  Start des PATCH bewirkt nichts mehr; `result` liefert dann den Erfolg.

## `management`

```dart
// vorher
await api.management.waitForIdle();
api.management.updateRuntimeSettings(multiRequest: true);
api.management.setDevice(device);

// nachher
await api.waitForIdle();
api.updateRuntimeSettings(multiRequest: true);
api.setDevice(device);
```

Ebenso direkt am Client: `hasPendingRequests`, `pendingRequestCount`, `isDisposed`, `device`,
`runtimeSettings`. `api.management.callbacks` entfällt mit den Callbacks.

## Request-Hook → `httpClient`

In 0.2 brauchte ein Eingriff in jeden Request eine Unterklasse von `DOCUframeApi` über den
`@internal`-Konstruktor und Importe aus `src/` (so verzögerte der Netzwerksimulator der App
V3-Aufrufe). In 0.3 genügt ein eigener `http.Client`:

```dart
class DelayingHttpClient extends http.BaseClient {
  DelayingHttpClient(this._inner, {required this._delay});

  final http.Client _inner;
  final Future<void> Function() _delay;

  @override
  Future<http.StreamedResponse> send(http.BaseRequest request) async {
    await _delay();
    return _inner.send(request);
  }

  @override
  void close() => _inner.close();
}

final api = GsdApiClient(
  configuration: configuration,
  httpClient: DelayingHttpClient(
    GsdApiClient.createHttpClient(allowSslError: configuration.allowSslError),
    delay: networkSimulator.delay,
  ),
);
```

- Der Client übernimmt den `httpClient` und schließt ihn in `dispose()`.
- `GsdApiClient.createHttpClient` erzeugt den Client, den er sonst selbst nutzt: auf IO mit
  `allowSslError` und `connectionTimeout`, im Web einen `BrowserClient`.
- Die HTTPS-Pflicht (`http://` nur mit `allowSslError`) gilt auch für einen übergebenen Client.
- Der Hook sieht jede HTTP-Anfrage: einen Login als zwei (Key, Login), ein gebündeltes
  `v1/multi` als eine, einen Upload als drei.

## Weitere Signaturen

- `remindBefore` der Termin-Methoden (`postAppointments`, `patchAppointmentsUpdateAppointment`,
  `patchAppointmentsCreateException`) ist eine `Duration` statt `ISODuration`:
  `remindBefore: const Duration(minutes: 15)` sendet wie bisher `PT0H15M0S`.
- `v1.documents.uploadFile` und `uploadFileWithController` haben keine Parameter `patch` und
  `out` mehr; beide hatten keine Wirkung.

## Plattform

- Das Paket hängt nicht mehr von Flutter ab und läuft auf der VM und im Browser.
- `GsdUploadFile.fromPath` wirft im Web `UnsupportedError`; dort `GsdUploadFile.fromBytes`
  verwenden.
- Der AES-Schlüssel des Logins liegt nur noch im Speicher. Ein von `gsd_encryption` gespeicherter
  `encryption_key` bleibt im Secure Storage liegen und wird nicht mehr gelesen.
